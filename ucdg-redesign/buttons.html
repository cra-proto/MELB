Buttons

A button is a call to action — it invites the reader to do the one main thing on the page: apply, sign in, submit, continue. Because a button shouts, a page should have only one that shouts loudest. Every extra button competes with the real action and weakens it.

Choose the right pattern

Not everything clickable is a button. Decide by what the control does and how important it is.

Primary button

The one main action of the page — "Apply now", "Sign in". Use exactly one, and make it stand out.

Secondary button

A lesser action beside the primary one — "Back", "Cancel". Styled quieter so the primary action wins.

Text link

Use for navigation — sending the reader to another page. Navigation is a link, not a button.

Quick decision guide

  • The single main action of the page? → one primary button
  • A lesser action next to it? → secondary button
  • Going to another page? → text link, not a button
  • Several equal actions competing? → rethink; a page usually has one primary action

What to include

  • A label that names the action in verb-first, plain language — "Submit your return", not "OK"
  • One clear primary button per page or per step
  • A large, tappable target that works on a phone
  • A visible focus and pressed state

Guidance

  • Use one primary button per page. When several buttons compete, none reads as the main action.
  • Label the action, not the mechanism — "Sign in to My Account", not "Click here".
  • Use buttons for actions and links for navigation. Don't style a link as a button just to make it bigger, and don't make a button that only navigates.
  • Don't disable the primary button in a way that leaves the reader stuck with no explanation of what's missing.

Accessibility

  • Use a real <button> for actions and a real link for navigation, so assistive technology announces the correct role.
  • The button must be reachable and operable by keyboard, with a visible focus state.
  • The label must make sense on its own — a screen-reader user may hear it out of context.
  • Don't rely on colour alone to distinguish primary from secondary; use size, weight, and position too.

Examples

Compare buttons side by side

Good use of buttons
  • A service page with one primary button, "Sign in to My Account", and everything else as text links.
  • A form step with a primary "Continue" button and a quieter secondary "Back" button beside it.
Buttons to avoid
  • Five equally styled buttons in a row: Apply, Learn more, Contact, FAQ, Home.
    Why it is wrong: no single primary action. Use one button and make the rest text links.
  • A button labelled "OK" with no indication of what it does.
    Why it is wrong: the label must name the action. Use "Submit your return" or similar.
  • A "Next page" navigation styled as a big button.
    Why it is wrong: navigation is a link, not an action button. Use a text link.
