Interactive questions

An interactive question asks the user something on the page and then reveals only the content that applies to their answer. Use it to shrink long "if… then…" paragraphs into a short question the user can actually answer.

Choose the right pattern

Interactive questions are one of three ways to handle "it depends" content. Pick based on the user's task.

Interactive question

Use when the answer changes what the user sees, and each branch is short (a paragraph or two).

Static list of conditions

Use when the user is likely to read several branches to compare — for example, eligibility rules a couple compares side by side.

Separate page per situation

Use when each branch is long enough to be a page of its own, or the branches diverge in more than one dimension.

Quick decision guide

  • Does the user need to see all branches to decide? → Static list
  • Does each branch need its own page-worth of guidance? → Separate pages
  • Would the user's answer collapse the page to one or two paragraphs? → Interactive question

What to include

  • One question, worded so any user can answer it without reading anything else
  • Between 2 and 5 mutually exclusive answer options — never overlapping
  • A visible result panel for every answer, revealed as soon as the user picks
  • A "reset" affordance if the user changes their mind, unless the question is trivially re-answerable
  • Fallback content that reads sensibly if JavaScript is off — usually the same information as a static list

Guidance

  • Ask one question at a time. If a second question depends on the first, reveal it only after the first is answered.
  • Write the question in plain, second-person language. "Are you a resident of Canada?" not "Residency status of the applicant."
  • Answer options must not overlap. "1 to 5 employees" and "5 to 10 employees" both include 5 — rewrite to "1 to 4" and "5 to 10."
  • Never bury the answer inside another accordion. The result must appear directly under the question.
  • Do not use an interactive question to hide content the user should always see, like fees or deadlines.
  • Cap the depth. If you would need more than 3 nested questions, the content belongs on separate pages.

Recommended question patterns

  • Are you [role]? — Yes / No
  • Which of these describes your situation? — 2 to 5 named situations
  • How would you like to [action]? — 2 to 4 channels (online, by mail, in person)
  • Which year are you filing for? — a small list of years

Accessibility

  • Every answer option is a real form control (radio or button), reachable and operable by keyboard.
  • The result panel uses aria-live="polite" so screen readers announce the reveal without stealing focus.
  • Do not rely on colour to distinguish the currently selected option — the state must be visible in the control itself.
  • Provide a "start over" button when the user has drilled several levels in, so they can escape without page reload.

Examples

Compare question patterns side by side

Good interactive question examples
  • Are you filing on behalf of someone else? — Yes / No. Selecting Yes reveals a short paragraph about Represent a Client with one link. Selecting No reveals the standard filing steps.
    Why it works: one clear question, mutually exclusive answers, each branch is short enough to read on the page.
  • Which best describes your business? — Sole proprietor / Partnership / Corporation. Each answer reveals the two or three sections the user needs and hides the rest.
    Why it works: named situations, no overlap, dramatically shorter than showing every business type on one page.
  • How would you like to submit? — Online (My Account) / By mail. Reveals the correct set of steps for the chosen channel. Includes a "Change channel" button on the result.
    Why it works: channel choice is a natural fork, and the reset button acknowledges people change their minds.
Interactive questions to avoid
  • Which of the following best describes the nature of your inquiry from the perspective of the taxpayer? — 12 options.
    Why it is wrong: unanswerable without reading the whole page, and 12 options is a menu, not a question. Split into a hub page with 12 links.
  • How many employees do you have? — 1–5 / 5–10 / 10+.
    Why it is wrong: the ranges overlap at 5 and 10. Someone with 5 employees does not know which to pick.
  • Are you eligible for the credit? — Yes / No / I do not know.
    Why it is wrong: eligibility is what the page is supposed to tell them. Asking the user to self-assess before you help them is backwards.
  • Question 1 of 5: a five-question wizard with each answer revealing the next question, ending in a very long result panel.
    Why it is wrong: five nested questions with a heavy end-state means the branches are long enough to be their own pages — use the subway pattern instead.
