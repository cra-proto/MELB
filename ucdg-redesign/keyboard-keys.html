Keyboard keys

The keyboard key effect styles text to look like a physical key on a keyboard — Ctrl, Enter, Tab. Use it only when you are telling the reader which key to press, so the instruction reads as a key and not as ordinary text.

On this page

  • When to use it
  • Guidance
  • Accessibility
  • Examples

When to use it

  • Use it only for a real keyboard key the reader is meant to press — Esc, Alt, a letter, an arrow key.
  • Show a key combination as separate keys joined by "+": Ctrl + S.
  • Match the label to what is printed on the key.

Guidance

  • Do not use the key effect for emphasis, buttons, or on-screen controls — it means "press this physical key" and nothing else.
  • Keep keyboard instructions rare. Most CRA tasks are done with a mouse or touch; only mention keys when they genuinely help.
  • Name on-screen buttons by their label in plain text (for example, "select Submit"), not with the key effect.

Accessibility

  • Use the semantic <kbd> element so assistive technology can recognise the text as keyboard input.
  • Don't rely on the visual "key" look alone — the key name must be readable text, not an image.
  • Spell out the key name a screen reader can announce clearly (for example, "Control" is conveyed by the visible Ctrl label in context).

Good use of keyboard keys
  • "To save your progress, press Ctrl + S." — a genuine key instruction, styled as keys.
  • "Use the Tab key to move between fields." — helps keyboard users navigate a form.
Keyboard keys to avoid
  • Styling the word important as a key for emphasis.
    Why it is wrong: the key effect means "press this key". Use bold for emphasis.
  • Showing the on-screen Submit button with the key effect.
    Why it is wrong: Submit is a button, not a keyboard key. Name it in plain text.
