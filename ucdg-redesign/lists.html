Lists

A list turns a run-on sentence of items into something a reader can scan. Most content that feels dense is really a list waiting to happen. Choose the list type by what the items are — a set, a sequence, or a set of term-and-definition pairs — and the reader will understand the relationship at a glance.

Choose the right pattern

There are three list types. Pick by the relationship between the items, not by how the list looks.

Bulleted (unordered)

Use when the items are a set and their order doesn't matter — accepted documents, things you'll need, options.

Numbered (ordered)

Use when order matters — steps to follow, ranked items, or anything the reader does in sequence. Also alpha or roman.

Description list

Use for term-and-definition pairs — a glossary, a set of fields and their values, name/description rows.

Quick decision guide

  • Does the order of items matter? → Numbered list
  • Is it a set where order is irrelevant? → Bulleted list
  • Is each item a term paired with a definition? → Description list
  • Do the items share the same attributes you need to compare across them? → consider a Table instead

What to include

  • A lead-in line that introduces the list and ends with a colon, so the list has context
  • Items in parallel structure — all fragments, or all full sentences, all starting the same grammatical way
  • The right marker: bullets for a set, numbers for a sequence, a term/definition pair for a description list
  • Short items — if an item runs to several sentences, it may need to be a paragraph or its own subsection

Guidance

  • Write a clear lead-in. "You will need:" tells the reader what the list is before they read it.
  • Keep items parallel. Mixing verbs, nouns, and full sentences makes a list harder to scan.
  • Don't force order onto a set, or drop order from a sequence. The marker is a signal — use it honestly.
  • Avoid nesting more than one level deep. Deep nesting is hard to follow; restructure instead.
  • Don't use a list purely for visual spacing. A single item is not a list.

Enhancements

The design system offers styled variations of the basic list. Use them when they help the reader, not for decoration:

  • Icon list: replace bullets with green checkmarks and red X marks to show "do / don't" or "included / not included".
  • Multiple columns: spread a long single-level list across columns when the items are short and the list is otherwise very tall.
  • And / or pattern: make the combinator explicit when a list of criteria could be misread (see And / Or).
  • Search filter: add a filter to a long list the reader will scan for one item — for example, a list of tax slips.
  • Menu-style list: a list of links that acts as a directory to other pages.
  • Interactive checklist: let the reader tick off items — useful for "get ready to apply" steps.

Accessibility

  • Use real list markup (<ul>, <ol>, <dl>). Screen readers announce the list type and item count — dashes or line breaks do not.
  • In an icon list, the meaning must be in a visible label or the item text, not the icon alone; mark decorative icons aria-hidden="true".
  • Keep multi-column lists to a single level so the reading order stays clear when columns reflow on a phone.
  • An interactive checklist must be operable by keyboard, and its checked state exposed to assistive technology.

Examples

Compare lists side by side

Good lists
  • Numbered for steps: "To file online: 1. Sign in to My Account. 2. Select Tax returns. 3. Follow the prompts." — order matters, so the list is numbered.
  • Bulleted for a set: "You will need: your SIN, your T4 slips, your notice of assessment." — order doesn't matter.
  • An icon list of accepted vs not accepted documents, green checks and red X marks with the meaning in the text.
Lists to avoid
  • A set of unrelated options written as a numbered list.
    Why it is wrong: numbers imply a sequence that doesn't exist. Use bullets for a set.
  • A list mixing "Sign in", "Your SIN", and "You must file by April 30" as items.
    Why it is wrong: no parallel structure — actions, nouns, and a full sentence jumbled together. Split and make them parallel.
  • A list built with hyphens and line breaks instead of real list markup.
    Why it is wrong: screen readers don't announce it as a list. Use <ul> / <ol>.
  • A three-level nested bulleted list.
    Why it is wrong: deep nesting is hard to follow. Restructure with headings or separate lists.
